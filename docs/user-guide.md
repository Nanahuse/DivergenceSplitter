## Monitor

Monitorでは、各シナリオが判定に使う映像を確認できます。表示するのはCrop／Resize後の画像です。入力欄には判定用に渡されたフレームの数、映像の取得速度（FPS）、取得中かどうかを表示します。

表の各行は1つのシナリオとLiveSplitへの接続の組に対応します。この組をインスタンスと呼びます。各行には接続状態、タイマーの状態（Phase）、現在のSplit位置、最後に要求した操作（Action）、エラーや操作結果を表示します。シナリオやSplitの番号は0から始まります。

Processing FPSは、各インスタンスが1秒あたりに映像を判定した回数です。映像を受信する速度とは別の値で、同じ映像でもインスタンスごとに異なる場合があります。

Current evaluationには、現在の判定条件（Condition）と、その状態を表示します。画像の判定（Detector）を実行した場合は、しきい値と最新スコアを表示します。表示中にポインターを置くと、追加の行が確認できます。このバージョンには専用のDiagnostics画面はありません。Condition全体の構造と最大スコアはMonitorのカードに表示されます。PendingやWaiting for Reset confirmationは、[操作の確認待ち](troubleshooting.md#操作の確認待ちとresetの実行)で説明します。

Readyは、Bridgeとの接続とタイマー情報の同期が済んだ状態です。映像が届いているか、条件が成立しているか、シナリオの区間数がLiveSplitと合っているかは、それぞれ別に確認してください。接続が切れているインスタンスでは、タイマー操作の判定を行いません。他のインスタンスはそれぞれの接続状態に従って動作します。

### Reset All

Reset Allを2秒間押し続けると、各インスタンスにタイマーのResetを要求します。2秒経つ前に離すか、ポインターをボタンの外へ動かすとキャンセルできます。

要求を処理できるインスタンスから、Running、Paused、EndedのタイマーにResetを送ります。すでに停止しているタイマーには送りません。すべてのLiveSplitで同時に成功するとは限らないため、各行の操作結果を確認してください。

Reset Allはタイマーをリセットする操作です。下書きやProfileファイルを削除しません。リセット後に開始条件が成立すると、Runが再び始まることがあります。

## Profileの下書き・適用済み設定・ファイル

Profileでは、映像入力と画像変換、各インスタンスのBridgeポートとシナリオのファイルパスを設定します。入力と画像変換は、すべてのインスタンスで共通です。

Add instanceで行を追加し、Remove instanceで削除します。Browse scenario...では、その行で使うシナリオを選びます。入力の設定項目と保存するJSONの形式は、[設定リファレンス](configuration.md)を参照してください。

| 操作 | 動作 |
| --- | --- |
| 項目を編集 | 編集中の下書きだけが変わります。実行中のシナリオには、まだ反映されません。 |
| Apply | シナリオと参照画像を読み込み、選んだ入力を検証して、下書きの設定で実行を始め直します。映像取得と各インスタンスの状態をリセットし、動画は先頭に戻します。Profileのファイルには保存しません。 |
| Revert draft | 下書きを、現在適用している設定に戻します。ファイルの読み直しや、送信済みのタイマー操作の取り消しは行いません。 |
| Profile画面のOpenボタン | JSONを読み込んですぐに適用し、下書きも置き換えます。 |
| Profile画面のSave Asボタン | 現在の下書きをJSONに書き、パスを記憶します。下書きの適用や完全な検証は行いません。 |

設定するときは、まず下書きを編集し、プレビューで入力映像を確認してください。続いてApplyを押し、Monitorで動作を確認してから保存します。Applyの前に保存すると、未適用の設定や、正しく動かない設定をファイルに残す場合があります。

映像入力を開く処理はApplyの後も続くため、Applyが成功してから入力エラーが表示される場合があります。Monitorで結果を確認し、必要な修正をしてから、もう一度Applyしてください。

YAMLや参照画像を編集して保存しても、自動では読み直しません。変更を反映するにはProfileを再びApplyするか、開き直してください。

Profileを開くか保存すると、アプリはそのパスを記憶します。次回起動時にそのファイルが残っていれば、自動で読み込んで適用を試みます。

### 入力の下書きプレビュー

Draft input previewは、編集中の入力をApply前に確認するための表示です。ProfileでPreview inputを有効にすると、シナリオを実行していない間にCamera／Video／NDIの映像を確認できます。

表示するのは、開いた入力の寸法、入力側が報告するFPS（取得できる場合）、実際に受信したFPS、変換後の寸法です。Crop／Resizeだけを変えた場合は、入力を開き直さずに表示を更新します。送信元が一時停止していても、最後に受信した画像で変換結果を確認できます。

プレビューは入力と画像変換の確認用です。シナリオの評価やBridge操作は行いません。Resize reference imagesによる参照画像の変換もここでは確認できないため、Apply後にMonitorで判定を確認してください。

シナリオの実行中は、下書きプレビューのために別の入力を開きません。Stop Session and preview draftを押すと実行を止め、編集中の入力を確認できます。Applyを押すと、シナリオの実行を再開します。

Profileから別の画面へ移ったとき、Preview inputをオフにしたとき、またはシナリオの実行を始めたときに、プレビューの入力を閉じます。動画はプレビュー中も再生されますが、Applyすると先頭に戻ります。プレビューでエラーが出たら入力を修正するか、Preview inputを切り替えて再試行してください。

## Settings

- Log level：記録するログのレベルを `OFF`、`DEBUG`、`INFO`、`WARNING`、`ERROR` から選びます。既定値は `INFO` です。記録対象を絞り込む設定なので、DEBUGにしても全フレームのDetectorスコアを記録するわけではありません。
- Reaction time：映像を取得してから自動操作を送るまでの待ち時間を、ミリ秒で指定します。0以上の値を指定でき、既定値は `0`、画面上の上限は `5000` です。判定処理にかかった時間も、この待ち時間に含みます。Resetでは待ち時間を省く場合があります。詳しくは[Actionの保留と確定待ち](scenarios/yaml-reference.md#actionの保留と確定待ち)を参照してください。この設定は判定のしきい値ではなく、タイマーを操作する正確な時刻を保証するものでもありません。
- Theme：LightまたはDarkを選びます。保存すると画面の配色が変わります。

SaveでSettingsの内容を保存します。Reloadは、アプリが記憶している保存済みの値を画面に戻す操作です。Reaction timeとログレベルの変更を実行中のシナリオに反映するには、Profileを再びApplyしてください。

SettingsはProfileとは別のファイル `%APPDATA%/DivergenceSplitter/settings.json` に保存します。全項目の形式は[設定リファレンス](configuration.md#アプリケーション設定)を参照してください。
