# Detectorリファレンス

[日本語（正本）](detectors.md) | [English](detectors.en.md)

[シナリオ作成](README.md) · [detected](conditions.md#detected) · [例](examples.md)

Detectorは画像を調べて結果を数値のスコアにする判定方法です。[`detected`](conditions.md#detected) は、そのスコアが `minimum_score` 以上なら成立します。

使えるDetectorは9種類で、スコアはすべて `[0, 1]` の範囲です。方式に応じて、画像の一致度、明るさ、指定色の割合が高いほど大きくなります。スコアは確率ではなく、方式が違えば同じしきい値をそのまま使えるとは限りません。Diagnosticsで、検出したい画面と検出したくない画面の両方を比べて調整してください。

以下の式にある `clamp` は値を `[0, 1]` の範囲に収める処理を表します。

## 共通設定とROI

すべてのDetectorで、`type` に判定方法を指定します。`roi` は、映像のどの範囲を調べるかを指定する項目です。参照画像と比べる方式では、その画像のパスを `reference` に記述します。

`hash_size` を指定できるのは `difference_hash_similarity` だけです。`lower` と `upper` は `color_range` だけで使います。これら以外の設定項目はありません。

```yaml
type: template_match
reference: images/title.png
roi: {x: 100, y: 50, width: 320, height: 180}
```

`roi` を省略するか `null` にすると、Crop／Resize後の画像全体を調べます。一部だけを調べる場合は、`x`、`y`、`width`、`height` の4項目をすべて整数で指定してください。

`x` と `y` は左上の位置で、0以上です。`width` と `height` は範囲の幅・高さで、0より大きい値を指定します。座標の基準はCrop／Resize後の画像の左上です。指定した範囲が映像からはみ出すとエラーになり、自動では切り詰めません。

ROIは入力映像から調べる範囲を選ぶ設定です。参照画像の一部を切り取る設定ではありません。以下の寸法の条件は、選んだ映像の範囲と参照画像を比べたときの条件です。

## 参照画像とチャンネル

参照画像の相対パスは[YAMLの保存場所](yaml-reference.md#パス)を基準にします。通常は8ビットのカラーPNGを用意してください。読み込み時に、チャンネル数やビット深度を一律には変換しません。

チャンネルは画素を構成する色などの成分です。グレースケールは1チャンネル、BGRは青・緑・赤の3チャンネル、BGRAはそれに透明度のalphaを加えた4チャンネルです。グレースケールPNGを読み込んでも、自動でカラーのBGR画像にはなりません。

参照画像として読み込めるのは、1チャンネルのグレースケール、3チャンネルのBGR、4チャンネルのBGRAです。ただし、判定方法によって、さらに制約があります。

BGRAのalphaには、完全に透明な0か、完全に不透明な255だけを使ってください。半透明のピクセルがある画像や、すべて透明な画像は使えません。すべて不透明ならalphaを取り除き、マスクなしの画像として扱います。一部が透明な画像では、方式ごとに次のように扱います。

| Detector | 入力と参照画像の寸法・チャンネル | 透過ピクセルの扱い |
| --- | --- | --- |
| `template_match` | 参照の幅・高さは領域以下。alpha除去後のチャンネル数が一致すること。 | 二値マスクで相関を計算。 |
| `mean_absolute_similarity`、`root_mean_square_similarity` | 幅・高さと、alpha除去後のチャンネル数が完全一致。 | 誤差と成分数から除外。 |
| `histogram_similarity`、`perceptual_hash_similarity` | 入力は8ビットBGR、参照は8ビットBGR／BGRA。マスクなしなら寸法が異なってもよく、ありなら領域と完全一致。 | histogramは除外し、perceptual hashは両画像の同じ位置を黒にする。 |
| `difference_hash_similarity` | 寸法の違いとグレースケール／BGR／BGRAを許容し、グレースケールへ変換。 | alphaを検証して除くが、マスクは使わない。 |
| `phase_correlation` | 幅・高さが完全一致。グレースケール／BGR／BGRAを浮動小数点グレースケールへ変換。 | alphaを検証して除くが、マスクは使わない。 |

`template_match` と画素ごとの誤差を比べる方式では、入力と参照画像のチャンネル数を合わせてください。通常のBGR映像に対して、グレースケールの参照画像を自動でBGRへ変換することはありません。

画素の誤差は浮動小数点で計算しますが、スコアの基準値は255なので、参照画像には8ビットが適しています。`template_match` は計算に使える8ビットまたは浮動小数点の画像に変換しますが、16ビットの画素値を0～255の範囲へ変換する処理は行いません。

`histogram_similarity` と `perceptual_hash_similarity` では、8ビット以外の参照画像を使えません。hashやphaseの方式は、グレースケールを浮動小数点に変換して計算します。空の画像や、形式が条件に合わない画像は、読み込み時または判定時のエラーになります。検出成功として扱うことはありません。

Profileの [`resize_references`](../configuration.md#cropresize参照画像) を有効にしている場合は、読み込み時に参照画像の寸法が変わります。Applyで参照画像自体は検証しますが、ROIの範囲や、実際の映像と寸法・チャンネルが合うかを確認するには、映像のフレームが必要です。

## 方式の選び方

| 用途 | 最初に試す方式 |
| --- | --- |
| 領域内の異なる位置から特徴的な小画像を探す | `template_match` |
| 固定した画面・ROIを画素単位で比べる | `mean_absolute_similarity` |
| 大きな画素誤差を強く減点する | `root_mean_square_similarity` |
| 配置より色の分布を比べる | `histogram_similarity` |
| 寸法が違う画像のおおまかな構造を比べる | `perceptual_hash_similarity`、`difference_hash_similarity` |
| 参照なしで明暗の変化を調べる | `mean_brightness` |
| 領域内の指定色の割合を調べる | `color_range` |
| 同寸法の画像を平行移動に対応した相関で比べる | `phase_correlation` |

この表を目安に方式を選び、実際の映像で確認してください。hashやhistogramでは、別の画面でも高いスコアになる場合があります。調べる範囲をROIで絞る、他のConditionを組み合わせるなどして、判定したい場面と誤判定しやすい場面の両方を試してください。表だけで精度を保証するものではありません。

## template_match

```yaml
type: template_match
reference: images/title.png
```

参照画像をテンプレートとして、選んだ範囲のどこに映っているかを探します。`reference` は必須で、`roi` は省略できます。テンプレートが収まるすべての位置で正規化相関を計算し、最も高い値をスコアに使います。

- マスクなし：OpenCVの `TM_CCOEFF_NORMED` でチャンネルごとの平均を差し引きます。最大相関 `r` の範囲は `[-1, 1]` で、スコアは `clamp((r + 1) / 2)` です。相関0のスコアは約 `0.5` であり、0ではありません。
- マスクあり：不透明ピクセルで `TM_CCORR_NORMED` を計算します。同じ平均除去は行わず、最大相関を直接 `[0, 1]` に制限します。

参照画像には少なくとも1つのチャンネルで、場所による色や明るさの違いが必要です。一様な画像は使えません。参照画像が調べる範囲より大きい場合や、チャンネル数が合わない場合は、判定エラーになります。相関値がNaNや無限大になった場合もエラーです。

大きさが変わらない記号や文字を探す用途に向きます。拡大縮小や回転を試しながら探す機能はありません。また、一致した位置をConditionへ渡す機能もありません。

## mean_absolute_similarity

```yaml
type: mean_absolute_similarity
reference: images/screen.png
```

同じ位置の画素を比べ、差の平均が小さいほど高いスコアにします。`reference` は必須で、`roi` は省略できます。

不透明な画素の成分数を `N`（不透明ピクセル数×チャンネル数）、入力と参照の各成分の差を `d_i` とすると、スコアは `clamp(1 - (sum(abs(d_i)) / N) / 255)` です。

同じ画像ならスコアは1で、画素の差が平均して大きいほど下がります。入力と参照画像の幅・高さ・チャンネル数は、すべて一致させる必要があります。位置が固定されたUIや画面の比較に向きますが、移動、圧縮ノイズ、明るさの変化でもスコアが下がります。

## root_mean_square_similarity

```yaml
type: root_mean_square_similarity
reference: images/screen.png
```

画素の差を二乗して比べるため、大きな誤差を強く反映する方式です。`reference` は必須で、`roi` は省略できます。比較する成分はmean absolute方式と同じで、スコアは `clamp(1 - sqrt(sum(d_i * d_i) / N) / 255)` です。

入力と参照画像の幅・高さ・チャンネル数を、すべて一致させてください。画面の一部に大きな違いがあるとき、mean absolute方式よりスコアを大きく下げたい場合に使います。

## histogram_similarity

```yaml
type: histogram_similarity
reference: images/screen.png
```

色の分布を比べる方式です。`reference` は必須で、`roi` は省略できます。各色を8ビンに分け、合計512ビンのRGB結合ヒストグラムを作ります。各色の値の範囲は `[0, 256)` で、L2正規化して比較します。

OpenCVのBhattacharyya距離を `D` とすると、スコアは `clamp(1 - D)` です。距離の計算では、ヒストグラム全体の量で係数を正規化してから平方根を取ります。色の分布が同じならスコアは1です。

入力は8ビットBGRにします。参照画像には8ビットBGRまたはBGRAを使えます。BGRAで一部を透明にした場合は、その部分を比べないよう二値マスクを使います。マスクを使うときは、参照画像と調べる範囲の寸法を一致させてください。マスクを使わなければ、寸法が違っていても比較できます。

色がどこにあるかは比べません。画素の位置を入れ替えても、色の分布が同じならスコアが1になる場合があります。画面全体の配色の変化には使えますが、似た配色の画面配置を、この方式だけで区別する用途には向きません。

## perceptual_hash_similarity

```yaml
type: perceptual_hash_similarity
reference: images/screen.png
```

画像のおおまかな特徴を64ビットのhashにして比べます。`reference` は必須で、`roi` は省略できます。

マスクで比較対象から外した画素は、両画像とも黒にします。area補間で8×8に変換し、exact linear補間で32×32へ拡大します。その後、8ビットグレースケール、浮動小数点の順に変換してDCTを行います。左上8×8の係数を取り、DC成分を0にして、各係数がその範囲の平均より大きいかどうかで64ビットのhashを作ります。

スコアは `clamp(1 - HammingDistance / 64)` です。違う画像でもhashが同じなら1になります。入力は8ビットBGR、参照画像は8ビットBGRまたは条件を満たすalpha付きのBGRAにしてください。マスクがなければ寸法は違っていてもよく、マスクがあれば一致させる必要があります。

大きさが違う画像のおおまかな構造を比べる用途に使えます。ただし、小さなhashにまとめるため、細部の違いを見落とす場合があります。

## difference_hash_similarity

```yaml
type: difference_hash_similarity
reference: images/screen.png
hash_size: 8
```

横に隣り合う画素の明るさの変化をhashにして比べます。`reference` は必須で、`roi` と `hash_size` は省略できます。`hash_size` には正の整数を指定し、既定値は8です。

浮動小数点のグレースケールに変換した画像を、area補間で `(hash_size + 1) × hash_size` にResizeします。右の値が左より大きい位置のビットを立て、`hash_size²` ビットを作ります。スコアは `clamp(1 - differing_bits / hash_size²)` です。

入力と参照画像は、寸法が違っていても比較できます。グレースケールとカラーの組み合わせも使えます。参照画像のalphaは有効な値かを確認して取り除きますが、透過部分を比較から除くマスクとしては使いません。

比較するのは横方向の明るさの変化で、色や正確な画素値ではありません。`hash_size` を大きくすると細部を記録できますが、計算量も増えます。違う画像が同じhashになる可能性を、なくすことはできません。

## mean_brightness

```yaml
type: mean_brightness
roi: {x: 0, y: 0, width: 100, height: 100}
```

参照画像を使わず、映像の明るさを調べます。`type` 以外に必須項目はありません。`roi` で調べる範囲を指定できます。

スコアは `clamp(mean_of_all_pixel_components / 255)` です。各チャンネルを同じ重みで平均し、人の感じる明るさに合わせた重み付けはしません。通常の8ビット入力では、黒が0、白が1です。

グレースケールとBGRを使えます。BGRAの場合はalphaも平均に含まれますが、通常のNDI入力では、判定前にalphaを取り除きます。

フェードなどの明暗変化を調べる用途に使えます。どの画面かを識別する方式ではありません。「しきい値より暗い」を条件にする場合は、`detected` を `not` と組み合わせてください。

## color_range

```yaml
type: color_range
lower: [0, 0, 180]
upper: [80, 80, 255]
```

指定した色の範囲に入る画素の割合を調べます。`lower` と `upper` は必須で、`roi` は省略できます。上下限は同じ長さのリストにし、グレースケールなら1成分、カラーなら3成分を指定してください。カラーの並びはB、G、Rで、RGBやHSVではありません。

リストの長さは入力のチャンネル数に合わせます。各値はNaNや無限大を除く数値とし、下限は上限以下にしてください。通常の映像の値は0～255ですが、この範囲外の設定値も読み込み時には拒否しません。

すべてのチャンネルが下限以上、上限以下の画素を数えます。境界の値も範囲に含みます。スコアはその画素数を調べた範囲の全画素数で割った `matching_pixels / total_pixels` です。

例では、主に赤い画素の割合を調べています。参照画像や色空間の変換は使いません。単色の表示や、画面に重ねて表示される色の判定に使えます。

## phase_correlation

```yaml
type: phase_correlation
reference: images/screen.png
```

位置が平行移動した画像の相関を調べる方式です。`reference` は必須で、`roi` は省略できます。入力と参照画像は同じ寸法にしてください。

両画像を浮動小数点のグレースケールに変換し、窓を指定せずOpenCVの `phaseCorrelate` を使います。スコアは、正規化した相関ピークの強さを表すresponseを `[0, 1]` に収めた値です。移動した距離そのものや、画素の誤差を直接比較した類似度ではありません。

どちらもグレースケールへ変換できる形式なら、入力と参照画像のチャンネル数は違っていても構いません。alphaは有効な値かを確認しますが、マスクとしては使いません。幅・高さは一致させる必要があります。

はっきりした相関のピークが出る模様を選んでください。一様な画像や、対応する位置が曖昧な模様は向きません。responseがNaNや無限大の場合は、判定エラーになります。
