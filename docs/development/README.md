利用者が指定できる設定は、[Profileリファレンス](../configuration.md)と[YAMLリファレンス](../scenarios/yaml-reference.md)にまとめています。読み込み処理や判定の動作を変えたときは、対応する文書も更新してください。仕様は画面の項目名から推測せず、実装とテストで確かめます。

日本語と英語の両方を用意するのは、利用者向けの文書だけです。対象は、ルートREADME、導入・利用ガイド、設定、Scenario・Condition・Detector、サンプル、トラブルシューティング、NDIランタイムの説明です。日本語版を正本とし、英語版はその翻訳とします。内容が異なる場合は、日本語版を優先してください。

開発・設計・ビルド・テスト・CI・配布の手順、移行受け入れ記録、テストデータの説明は、日本語だけで提供します。ライセンス原文や正式な法的通知は、この翻訳方針とは別に扱い、必要な原文を維持してください。

利用者向け文書の日本語版を直したときは、対応する英語版にも内容を反映します。設定キー、数値、コード例が両言語で一致していることと、リンクが開けることを確認してください。

文書ごとの役割も分けます。Scenarioリファレンスには設定と動作、シナリオ例には実現できる条件、利用ガイドには画面での操作を書きます。内部設計や実装上の判断は開発者向け文書にまとめ、同じ説明を各所に繰り返さないようにしてください。

YAMLの例を変えたときは、完全なシナリオにして `load_scenario` または既存のローダーテストで読み込んでください。JSONは `load_profile` で確認します。文法だけでなく、そのブランチが実際に受け付ける設定かを検証する必要があります。

相対リンクと見出しへのリンクも確認します。ローダーテストでは、実際の映像とROIが合うかは検証できません。その確認には、映像のフレームを使うテストが必要です。具体的な方法は[例の検証](testing.md#ドキュメントと例の検証)を参照してください。
