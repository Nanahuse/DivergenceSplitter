# Scenario Builder の使い方

Scenario Builder でタイマーを操作する条件を設定し、保存したシナリオを DivergenceSplitter で実行します。まずは参照画像を使わず、時間だけで Start と Split を試します。

## シナリオを作って自動 Split を試す

### 作業フォルダーを選ぶ

1. DivergenceSplitter の配布 ZIP を展開し、`ScenarioBuilder.exe` を起動します。Microsoft Edge WebView2 Runtime のインストールを求められた場合は、画面の案内に従ってください。
2. ツールバーの「作業フォルダ」で、シナリオと参照画像を置くフォルダーを選びます。新しいシナリオが開き、参照画像を置く `Asset` フォルダーが作られます。

### Start と Split を設定して保存する

1. 左側の「シナリオ条件」で「Start」を選びます。右側の「Properties」で `type` が `elapsed`、`duration` が `2s` になっていることを確認します。開始条件の判定が始まってから2秒でタイマーを開始する設定です。
2. 左側の「+ Split」を押し、「Split 1」を選びます。Split は LiveSplit の区間に対応します。
3. 中央の「+ Rule」を押し、追加した Rule の条件を選びます。Rule は条件とタイマー操作の組み合わせです。
4. 右側の「Properties」で `duration` を `3s` に変更します。「Split 1」に戻り、Rule の操作が `split` になっていることを確認します。
5. ツールバーの「保存」を押し、ファイル名を `test.yaml` にして作業フォルダーの直下に保存します。

### DivergenceSplitter で実行する

1. LiveSplit に1区間のテスト用 Run を用意し、タイマーを停止状態にします。LiveSplit.Bridge と入力映像を準備します。手順は [はじめに](https://github.com/Nanahuse/DivergenceSplitter/blob/main/docs/getting-started.md) を参照してください。
2. DivergenceSplitter の「Profile」で「Scenarios & Connections」を開きます。行がなければ「Add instance」で追加します。対象の行の「Browse」で `test.yaml` を選び、「Bridge port」を LiveSplit.Bridge のポートに合わせて「Apply」を押します。
3. 「Monitor」を開き、Capture にポインターを置き、フレーム数が増えていることを確認します。対象の Instance が Ready になることも確認してください。開始条件の判定が始まってから約2秒で Start し、区間の判定が始まってから約3秒で Split します。

テストを終えたら、映像を止めるか DivergenceSplitter を閉じてください。このシナリオは映像が届いた状態でタイマーを Reset すると、再び Start します。

## ゲームに合わせて区間と操作を設定する

LiveSplit の区間数と順番に合わせて、左側の「+ Split」で区間を追加します。区間を並べ替えるには、左端のハンドルをドラッグするか、行の上下ボタンを使います。自分で操作する区間を選んだら、中央の「手動区間に変更」を押します。

| 設定したいこと | 画面で選ぶ項目 |
| --- | --- |
| タイマーを開始する | 「シナリオ条件」の「Start」 |
| 実行中のタイマーをリセットする | 「シナリオ条件」の「Reset」の横にある「+」 |
| 終了後に最後の Split を取り消す | 「シナリオ条件」の「Incomplete」の横にある「+」 |
| 区間で条件が成立したら操作する | 対象の Split を選び、「+ Rule」 |
| 複数の条件が順に成立してから1回操作する | Rule の条件の `type` で `then` を選び、「+ 子 Condition を追加」で条件を並べます。 |

条件の編集画面から区間の Rule 一覧に戻るには、中央上部の「Split 1」などのリンクを押します。

## 画像が映ったら Split する

1. 対象の Split の Rule を選びます。「Properties」で条件の `type` を `detected` に変更します。画像を調べる Detector の `type` では `root_mean_square_similarity` を選びます。
2. `reference` の「変更」を押して、比較に使う参照画像を選びます。一覧にない画像は「＋ 新規追加...」で選べます。Scenario Builder が画像を `Asset` にコピーし、参照画像に設定します。
3. 画面の一部を比較する場合は、Detector の設定で `roi` を選び、「任意項目を追加」を押します。比較する範囲の左上の位置と幅・高さをピクセルで指定します。「入力画像を選択」でゲーム画面の静止画を開くと、指定した範囲を重ねて確認できます。
4. 保存したシナリオを DivergenceSplitter で適用し、「Monitor」で実際の映像を使って判定を試します。検出したい場面とそれ以外の場面でスコアを見比べ、Condition の `minimum_score` を調整します。

入力画像は範囲を確認するためのプレビューです。DivergenceSplitter で映像を切り取ったりサイズを変えたりする場合は、処理後の映像を基準に調べる範囲を指定してください。比較に使う参照画像は、調べる範囲と同じ大きさにそろえてください。

## 同じ条件を複数の区間で使う

各区間のクリア画面を同じ方法で判定し、比較する画像だけを変えたいときに、共通 Condition を使えます。

1. 共通にしたい条件を選び、右側の「共通 Condition として登録」で名前を付けます。
2. 別の区間の条件を選び、右側の一覧で登録した名前を選んで「共通Conditionを使用」を押します。
3. 参照画像を区間ごとに変更できるようにするには、左側の「共通Condition」で登録した条件を開き、参照画像の「公開」にチェックを入れます。
4. 画像を変更したい区間で共通 Condition を使っている条件を選び、「公開パラメーター」から画像を指定します。その区間で共通の画像に戻すには「共通定義の値に戻す」を押します。

共通定義で条件を追加したり既定値を変えたりすると、その定義を使う箇所にも反映されます。「公開」を解除した項目は、各使用箇所で共通定義の値に戻ります。

1か所だけ条件の構成を変えるには、その使用箇所で「独立したConditionにする」を押してください。

共通定義の中で別の共通定義を使っている場合は、内側で公開した項目を外側でも公開できます。内側の項目の公開をやめるには、先に外側の公開を解除します。

画像を調べる設定だけを使い回す場合は、左側の「共通Detector」で Detector を作ります。各条件の Detector 欄で作成した名前を選び、「共通Detectorを使用」を押します。

## 保存したシナリオを編集する

- 作業フォルダーの直下に保存したシナリオは、左側の「YAML」から開けます。別のフォルダーのシナリオを開くには、先に「作業フォルダ」を切り替えてください。
- 保存時にエラーが出たら、表示された内容に沿って設定を見直してください。保存に失敗した場合は、保存済みのファイルが残ります。
- Scenario Builder で保存し直したら、DivergenceSplitter の「Profile」で「Apply」を押してシナリオを読み込み直します。
- 従来形式のシナリオは DivergenceSplitter で引き続き実行できます。Scenario Builder で編集する場合は、新しいシナリオを作成してください。
- 「Undo」「Redo」でシナリオの編集を取り消したりやり直したりできます。「新規追加」で `Asset` にコピーした画像は「Undo」を押しても残ります。
